Odoo-Estados Financieros USD - May 12
VIEW RECORDING: 
Propósito de la reunión

Definir la estrategia de reporte en dólares para el cumplimiento con US GAAP.

Puntos clave

  - El problema: El método de conversión actual de Odoo (aplicar una sola tasa a todas las cuentas) no cumple con US GAAP. Revalúa incorrectamente activos no monetarios (p. ej., activos fijos, capital) que requieren una tasa histórica.
  - La solución: Se requiere una base de datos “espejo”, actualizada mensualmente a partir de los libros en pesos, para rastrear tasas históricas para cuentas específicas. Este es el proceso manual actual y el estado objetivo para la automatización.
  - El camino a seguir: El equipo investigará el módulo de Odoo “Consolidation” para ver si su función de “tasa histórica” puede configurarse para aplicar diferentes tasas a distintos tipos de cuentas, evitando un desarrollo a la medida.

Temas

Requisitos de reporte bajo US GAAP

  - Proceso actual: Se mantiene mensualmente una base de datos “espejo” manual para el reporte en dólares.
      - Partidas monetarias (p. ej., CxC, CxP): Convertidas a la tasa de la fecha de la transacción y luego revaluadas al cierre de mes.
      - Partidas no monetarias (p. ej., activos fijos, capital): Convertidas y mantenidas a su tasa histórica de adquisición/contribución.
      - Inventario: Gestionado mediante un Cardex en dólares separado para rastrear costos históricos para el COGS.
  - Justificación: Este método asegura el cumplimiento con US GAAP, que exige tasas históricas para activos no monetarios a fin de evitar ganancias/pérdidas artificiales por fluctuaciones cambiarias.

Limitaciones de la conversión estándar de Odoo

  - Funcionalidad: Los reportes nativos de Odoo convierten todos los saldos a una única tasa seleccionada por el usuario (p. ej., fin de mes, promedio).
  - Insuficiencia: Este método no es adecuado para US GAAP porque revalúa activos no monetarios que deben mantenerse a su costo histórico.

Solución propuesta: Módulo Odoo Consolidation

  - Propuesta: Investigar el módulo “Consolidation”, que tiene una opción de “tasa histórica”.
  - La pregunta: ¿Puede este módulo configurarse para aplicar diferentes reglas de conversión a distintos tipos de cuentas (p. ej., tasa histórica para activos fijos, tasa de fin de mes para efectivo)?
  - El riesgo: El módulo podría aplicar un solo tipo de tasa a todas las cuentas, lo que no resolvería el problema.

Necesidades de reporte y contexto de auditoría

  - Reportes principales: Estados financieros mensuales (PyG, Balance General, Balanza de Comprobación), utilidad bruta por producto y presupuesto.
  - Proceso de auditoría: Deloitte audita los libros en pesos. Los auditores en EE. UU. verifican el proceso de conversión a dólares revisando papeles de trabajo, no re-auditando transacciones individuales.

Próximos pasos

  - Pablo & Juritzen:
      - Investigar la función de “tasa histórica” del módulo de Odoo “Consolidation” para determinar si puede aplicar diferentes tasas a distintos tipos de cuentas.
      - Desarrollar una propuesta formal para automatizar el proceso de conversión a US GAAP.
      - Programar una reunión de seguimiento a través del chat grupal para presentar los hallazgos.
