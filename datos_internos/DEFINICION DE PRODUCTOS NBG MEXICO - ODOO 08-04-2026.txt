Definicion de Productos NBG Mexico -  Odoo - April 08
VIEW RECORDING: 
Propósito de la reunión

Definir la estructura del catálogo de productos y los requisitos de datos para Odoo.

Puntos clave

  - Catálogo unificado: Se utilizará un único catálogo de productos compartido entre las tres empresas (Naturberry, Naturag, Naturprime) para garantizar la consistencia de los datos.
  - Estrategia de SKU: Los SKUs de fruta y empaque deben coincidir con el sistema de EE. UU. para habilitar una futura integración. Los servicios y consumibles usarán una nueva secuencia interna alfanumérica (p. ej., FR00001).
  - Propiedad de los datos maestros: Un único "Coordinador de ERP" será el propietario de los datos maestros para prevenir errores. Todos los cambios requerirán un proceso formal de solicitud.
  - Método de costeo: Se utilizará el método estándar de "Costo promedio". El equipo investigará si esto puede calcularse por almacén para reflejar los costos logísticos, ya que el valor predeterminado es por empresa.

Temas

Estrategia del catálogo de productos

  - Objetivo: Crear un catálogo de productos único y unificado para las tres empresas para asegurar la consistencia de los datos.
  - Control de visibilidad: Los productos pueden restringirse a empresas específicas o hacerse visibles en todas.
      - Productos compartidos: El costo es el único atributo que puede variar por empresa.
      - Productos exclusivos: El producto solo es visible y utilizable por su empresa asignada.
  - Tipos de producto:
      - Almacenable: Fruta fresca, empaques, tarimas. Se rastrea el inventario.
      - Consumible: Insumos de oficina/limpieza. No se rastrea el inventario; se usa para registrar gastos.
      - Servicio: Renta, servicios públicos.

Campos y lógica de datos del producto

  - SKU / Referencia interna:
      - Fruta y empaque: Deben coincidir con el SKU del sistema de EE. UU. para habilitar una futura integración.
      - Servicios y consumibles: Se definirá una nueva secuencia interna alfanumérica (p. ej., FR00001).
  - Costeo:
      - Método: Estándar "Costo promedio".
      - Cálculo: De forma predeterminada, Odoo calcula el costo promedio por empresa, no por almacén.
      - Problema: Esto impide un seguimiento preciso de costos por gastos logísticos entre almacenes.
      - Acción: El equipo investigará si Odoo puede configurarse para costo promedio por almacén.
  - Ventas y precios:
      - Política de facturación: Se utilizarán "Cantidades entregadas" para asegurar que la facturación coincida con los embarques reales.
      - Precios: Las Listas de precios gestionarán precios específicos por cliente y sensibles al tiempo. El precio principal del producto se establecerá en cero para forzar el uso de listas de precios.
  - Inventario y trazabilidad:
      - Rastreo: Por "Lotes" para habilitar la trazabilidad por embarque.
      - Fechas de caducidad: No se utilizarán debido a la rápida rotación del producto.
      - Transferencias intercompañía: La función "Intercompany" de Odoo automatizará el proceso de órdenes de venta/compra entre empresas.
  - Compras:
      - Información de proveedor: La pestaña "Compra" almacenará precios específicos por proveedor, tiempos de entrega y fechas de vigencia, permitiendo a los compradores tomar decisiones informadas.
      - Política de facturación: Se utilizarán "Cantidades recibidas" para asegurar que el pago coincida con las entregas reales.
  - Contabilidad:
      - Clave SAT: Requerida para la facturación electrónica (timbrado).
      - Segmentación de ingresos: Las "Cuentas analíticas" clasificarán automáticamente los ingresos (p. ej., Importación, Exportación) con base en reglas (p. ej., grupo de cliente), eliminando errores manuales.
  - Exportación:
      - Campos requeridos: Peso, unidad de medida aduanera (UMT) y fracción arancelaria (fracción arancelaria).

Catálogo de proveedores y productores

  - Códigos de productor: Deben ser asignados por el equipo de EE. UU. para asegurar un código unificado en ambos sistemas.
  - Códigos de proveedor: Se definirá una nueva secuencia interna alfanumérica.
  - Manejo de divisas: Investigar la práctica estándar de Odoo para proveedores con múltiples divisas (p. ej., USD, MXN) a fin de evitar crear registros duplicados de proveedores.
