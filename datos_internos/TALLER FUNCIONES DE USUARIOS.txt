Propósito de la reunión

Revisar la gestión de usuarios y permisos de Odoo.

Puntos clave

  - Permisos granulares: Utilizar la función personalizada "Hide Specific Menu" para otorgar a los usuarios amplios derechos de Administrator y luego restringir el acceso a submenús específicos (p. ej., reportes, configuración). Esto evita las limitaciones del rol predeterminado User.
  - Archivado de usuarios: Archivar a los usuarios cuando se desvinculen. Esto preserva sus datos históricos (p. ej., registros de "Creado por") para auditorías y libera su licencia, ya que los usuarios archivados no se facturan.
  - Seguridad e Interfaz de Usuario (UI):
      - 2FA: Obligatoria para todos los usuarios para cumplir con los requisitos de auditoría.
      - Botón "Cancelar": Agregar un mensaje de confirmación para evitar pérdidas accidentales de datos.
      - Página de inicio: Se puede establecer una imagen de fondo personalizada en la pantalla de inicio de sesión.

Temas

El desafío de permisos en Odoo y la solución

  - Problema: Los roles predeterminados de Odoo (User vs. Administrator) son demasiado rígidos.
      - User → Carece de acceso a configuración y reportes.
      - Administrator → Otorga acceso total, requiriendo restricciones manuales.
  - Solución: Función personalizada de Inflexyon "Hide Specific Menu".
      - Método: Otorgar derechos de Administrator y luego ocultar los menús no deseados en cualquier nivel (menú padre, submenú o elemento).
      - Beneficio: Permite control preciso para roles complejos (p. ej., un agente de compras que necesita ver facturas pero no reportes financieros).

Gestión del ciclo de vida del usuario

  - Creación:
      - Los usuarios se pueden crear manualmente o mediante una plantilla para importación masiva.
      - El primer usuario de un perfil se puede duplicar para crear otros con los mismos permisos.
  - Salida:
      - Archivar (Recomendado): Preserva todos los datos históricos (p. ej., registros de "Creado por") para auditorías. Los usuarios archivados no cuentan contra el límite de licencias.
      - Eliminar (No recomendado): Elimina el registro del usuario, rompiendo los vínculos con los documentos que creó y dificultando las auditorías.

Mejores prácticas de seguridad y mejoras de UI

  - Autenticación de dos factores (2FA):
      - Requisito: Obligatoria para todos los usuarios para cumplir con los estándares de auditoría.
      - Activación: Los administradores pueden enviar invitaciones desde el registro del usuario.
  - Personalización de UI:
      - Página de inicio: Se puede establecer una imagen de fondo personalizada en la pantalla de inicio de sesión.
      - Botón "Cancelar": Se agregará un mensaje de confirmación para evitar pérdidas accidentales de datos.

Módulo de Aprobaciones para Requisiciones

  - Propósito: Gestiona solicitudes internas (p. ej., requisiciones de compra) antes de que se conviertan en documentos formales.
  - Flujo de trabajo:
    1.  El usuario crea una solicitud en el módulo Approvals.
    2.  La solicitud sigue una secuencia de aprobación definida (p. ej., Gerente → Compras).
    3.  Solo las solicitudes aprobadas avanzan a la siguiente etapa (p. ej., una Orden de compra formal).
