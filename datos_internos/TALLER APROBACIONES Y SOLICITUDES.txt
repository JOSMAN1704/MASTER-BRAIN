Odoo - Aprobaciones y Solicitudes - May 19
VIEW RECORDING: 
Propósito de la reunión

Definir y demostrar el flujo de trabajo de compras y aprobaciones en Odoo.

Puntos clave

  - Nuevo flujo aprobado: El módulo "Approvals" de Odoo reemplazará el proceso actual en Jotform. Automatiza las requisiciones con una aprobación en dos pasos (Gerente → Tania), creando una Orden de Compra (PO) directamente desde la solicitud aprobada.
  - Estrategia dual de compras: El sistema soportará dos métodos:
    1.  Requisiciones: Para artículos ad hoc, no inventariables.
    2.  Reglas Min/Máx: Para reabastecimiento automatizado de artículos de inventario (p. ej., empaques) basado en niveles de stock y pronósticos de producción.
  - Validación automática de facturas: Un control clave será la validación de facturas basada en XML. Odoo comparará automáticamente los datos del XML contra la PO línea por línea, bloqueando el pago si los valores no coinciden.
  - Controles por proveedor: Odoo hará cumplir reglas por producto y temporada, incluyendo:
      - Límites de gasto: Una cantidad máxima de compra por proveedor para la temporada.
      - Restricciones de producto: Limitar qué productos se pueden comprar a cada proveedor.
      - Automatización de precios: Autocompletar precios desde contratos estacionales para evitar errores de captura.

Temas

Proceso actual de requisición (Jotform)

  - Flujo: Solicitante → Jefe inmediato → Tania (Compras) → Proveedor → Cuentas por Pagar (AP).
  - Selección de proveedor: El solicitante sugiere un proveedor; Tania tiene la autoridad final para elegir una mejor opción.
  - Documentación: El solicitante debe adjuntar 1–2 cotizaciones para justificar el precio.
  - Pago: AP realiza una verificación final (p. ej., listas negras del SAT) antes del pago.

Demostración del módulo de Aprobaciones de Odoo

  - Configuración: Se crean categorías de aprobación por departamento (p. ej., Requisiciones Contabilidad), cada una con una cadena de aprobación en dos pasos:
    1.  Jefe inmediato
    2.  Tania (Compras)
  - Creación de requisición:
      - Los usuarios envían solicitudes mediante un formulario estándar de Odoo.
      - El formulario se personalizará con campos del Jotform actual (p. ej., Tipo de compra, Prioridad).
      - Decisión: El solicitante no ingresará precios; el sistema los autocompletará desde contratos con proveedores para asegurar la precisión.
  - Flujo de aprobación:
      - Paso 1 (Gerente): Recibe una notificación para aprobar o rechazar. El rechazo termina el proceso.
      - Paso 2 (Tania): Recibe una notificación después de la aprobación del gerente.
  - Generación de PO: Tania puede crear una PO directamente desde la requisición aprobada, eliminando la captura manual.
      - Flexibilidad de proveedor: Tania puede anular la elección de proveedor del solicitante. El sistema registrará este cambio en la bitácora de auditoría.
      - Opciones de documento: Tania puede enviar una Solicitud de Cotización (RFQ) o una Orden de Compra (PO) confirmada al proveedor.

Validación de factura y pago

  - Control central: Un botón personalizado "Cargar factura" requerirá tanto los archivos XML como PDF.
      - Validación XML: Odoo comparará automáticamente los datos del XML (RFC, cantidad, precio unitario, total) contra la PO línea por línea.
      - Acción ante discrepancias: Si los datos no coinciden, el sistema bloqueará la creación de la factura y solicitará corrección.
  - Carga de evidencias: Se añadirá un botón separado para subir evidencias (p. ej., fotos, remisiones).
      - Validación: Este proceso requiere revisión humana manual, ya que el sistema no puede verificar automáticamente el contenido de las evidencias.
      - Rechazo: Tania puede rechazar evidencias y enviar una notificación al proveedor mediante el chat de Odoo, manteniendo toda la comunicación en la PO.
  - Prevención de facturas duplicadas: Odoo usará el identificador único del XML (UID) para evitar vincular la misma factura a múltiples POs, bloqueando pagos duplicados.

Gestión de proveedores e inventario

  - Materiales de empaque: Las compras se gestionarán con una estrategia dual:
      - Reglas Min/Máx: Para reabastecimiento automatizado basado en niveles de stock y pronósticos de producción.
      - Requisiciones: Para necesidades ad hoc o picos de producción.
  - Restricciones de proveedor: Odoo hará cumplir contratos estacionales por producto.
      - Mecanismo: La relación producto-proveedor incluirá Fecha Inicio, Fecha Fin y un límite de Cantidad para la temporada.
      - Aplicación: El sistema bloqueará requisiciones de productos fuera del rango de fechas válido o después de alcanzar el límite de cantidad.
  - Desempeño de proveedores: El equipo solicitó una forma de clasificar proveedores (p. ej., A, B, C) según métricas de desempeño como tiempo de entrega e incidentes de calidad. Se explorará como una mejora futura.

Presupuesto y facturación a productores

  - Control presupuestal:
      - Estructura: Los presupuestos se establecerán anualmente por departamento, no por empleado individual.
      - Aplicación: Odoo bloqueará requisiciones que excedan el presupuesto del departamento.
      - Excepción: Se requerirá un proceso formal de aprobación para exceder el presupuesto.
  - Facturación a productores:
      - Objetivo: Mejorar la transparencia para los productores vinculando sus cargos de servicio directamente a las facturas de los proveedores.
      - Acción: Gloria negociará con proveedores clave (p. ej., laboratorios) para recibir facturas desglosadas por productor individual.

Próximos pasos

  - Robert/Victor: Compartir la plantilla actual de Jotform con Emiliano para guiar la personalización del formulario en Odoo.
  - Gloria: Negociar con proveedores la facturación desglosada por productor e informar sobre su viabilidad.

      - Implementar control presupuestal por departamento.
