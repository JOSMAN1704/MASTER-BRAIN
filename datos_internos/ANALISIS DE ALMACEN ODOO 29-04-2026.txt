Propósito de la reunión

Revisar el análisis del almacén para definir qué se cubre de forma nativa en Odoo y qué requiere desarrollo a la medida.

Puntos clave

  - Necesidades básicas de inventario cubiertas de forma nativa: Las funciones estándar de Odoo (existencia en tiempo real, trazabilidad por lotes, reabastecimiento min/máx) reemplazarán el seguimiento actual en Excel.
  - Personalizaciones críticas requeridas: Procesos clave como digitalizar la papelería de entrega (firmas, fotos) y gestionar las entregas de materiales a productores requieren desarrollo a medida.
  - La planificación de producción de planta es una nueva prioridad: Se necesita una reunión dedicada con Eder para definir requisitos de gestión de calendarios de producción de planta y contratos de vivero.
  - Reunión de priorización agendada: Hay una reunión programada para mañana a las 4 PM para priorizar todos los desarrollos identificados para el Go-Live de agosto.

Temas

Objetivos de inventario de almacén

  - Objetivo: Reemplazar el seguimiento en Excel con un sistema unificado para visibilidad de existencias y trazabilidad en tiempo real.
  - Capacidades clave:
      - Control preciso de existencias: Visibilidad en tiempo real de materiales, plantas y fruta en todas las ubicaciones, incluyendo la existencia “aparente en campo” de productores.
      - Trazabilidad por lotes: Seguimiento de extremo a extremo (OC → Recepción → Venta) para control de calidad y reclamaciones.
      - Estrategia de retiro: FIFO (PEPS) para fruta, configurable por categoría de producto.
      - Historial de movimientos: Registros detallados de todas las transferencias, consumo y merma.
      - Gestión de merma: Registrar pérdidas a una ubicación de “merma”, asegurando el costo de inventario correcto y evitando inflación de existencias.

Funcionalidad nativa de Odoo

  - Reportes:
      - Historial de movimientos: Registros detallados con filtros (proveedor, producto, fecha).
      - Existencias en tiempo real: Listas de inventario por almacén (Materiales, Cuartos Fríos, Irapuato).
  - Reabastecimiento:
      - Reorden min/máx: Reglas que generan automáticamente órdenes de compra para mantener niveles de inventario.
  - Transferencias:
      - Entre almacenes: Transferencias internas estándar (“albaranes”).
      - Entre compañías: Funcionalidad nativa para transferencias entre Naturberry y Naturagui.
  - Devoluciones:
      - Devoluciones a proveedor: Proceso estándar para devoluciones totales, parciales o por intercambio.
      - Devoluciones de productor: Funcionalidad nativa, pero puede requerir desarrollo para cubrir el proceso completo.
  - Recepción:
      - Flujo estándar: Proceso nativo de 1, 2 o 3 pasos (p. ej., Recepción → Control de Calidad → Stock).
      - Control de calidad: Odoo tiene un módulo básico de CC; podría requerirse una solución a medida si resulta insuficiente.
  - Gestión de productos:
      - Lotes: Funcionalidad nativa para rastrear partidas de producto.
      - Fechas de caducidad: Funcionalidad nativa con alertas configurables.
      - Ubicaciones: Funcionalidad nativa para gestionar ubicaciones físicas de almacén (racks, pasillos).
      - Escaneo de código de barras: Herramienta nativa que funciona con teléfonos/tablets; pueden requerirse escáneres especializados para etiquetas dañadas.
  - Envíos directos:
      - Triangulación: Funcionalidad nativa para envíos directos proveedor→cliente, pero requiere desarrollo para ajustarla al flujo de entregas de productores.
  - Almacén de cuarentena:
      - Nativo: Odoo soporta crear múltiples almacenes para propósitos específicos.

Desarrollos a medida requeridos

  - Papelería digital de entrega:
      - Meta: Reemplazar las “papeletas” en papel con un flujo digital en tablets/teléfonos.
      - Funciones: Firmas digitales, evidencia fotográfica, notificaciones automáticas por correo.
  - Control de entrega de materiales a productores:
      - Proceso: El chofer presenta INE → El almacén escanea el código de barras del productor → El sistema valida:
          - Aprobación: El productor está autorizado por el responsable de Inocuidad.
          - Lista de materiales: El productor solo puede recibir materiales preaprobados.
      - Evidencia: Requerir foto de la INE del chofer y aprobación del responsable antes de la entrega.
  - Automatización de entrega y venta de plantas:
      - “Papeleta de Entrada y Salida”: Un formulario digital para que los asesores de campo registren la recepción de plantas y la entrega inmediata a productores.
      - Creación de pedido de venta: Generar automáticamente el pedido de venta a partir del registro de entrega.
  - Automatización del seguimiento de merma:
      - Meta: Automatizar el cálculo de merma y su reporte en los pedidos de venta.
      - Proceso: Registrar la cantidad total entregada y el porcentaje de merma → El pedido de venta refleja la cantidad neta, con la merma registrada para visibilidad del productor.
  - Gestión de fletes:
      - Módulo: Usar el módulo nativo de Odoo “Floquilla” (Fletes).
      - Necesidades: Una base de datos de transportistas y un proceso para la planeación semanal de fletes.
  - Proceso de devoluciones de productor:
      - Lógica: El sistema debe impedir que los productores devuelvan más material del que recibieron.
      - Evidencia: Requerir evidencia fotográfica para todas las devoluciones.
  - Gestión de reclamaciones a proveedores:
      - Proceso: Un flujo formal para rastrear reclamaciones de asesores de campo hacia compras/almacén.
      - Necesidades: Un sistema para gestionar el estado de la reclamación (aceptada/rechazada) y notificar al asesor.
  - Integración con sistema de tarimas:
      - Necesidad: Integración por API con el sistema externo de tarimas (pallets).
      - Acción: Robert enviará la documentación del API.
  - Integración NBG USA (Annoblech):
      - Necesidad: Permitir que NBG USA consulte inventario y cree pedidos de venta.
      - Estatus: Requisito conocido desde el alcance inicial del proyecto.
